1. Scope

  • All 107 baseline transcripts (baseline/transcripts): 76 LINK/COMMAREA transcripts replayed on legacy via the harness (legacy/run-transcript.sh semantics, legacy/tools/harness.py) and on the migrated service via the REST API of docs/migration/api-contract.md; 31 terminal-mode (BNKMENU/BNK1*) transcripts replayed through the migrated 3270 screen handlers.

  • 6 multi-step user journeys (parity/flows/user-flows.json): onboarding, payments, maintenance+close, error paths, customer lifecycle, REST teller - 31 steps, one database per journey, compared after every step.

Normalisation: CHAR right-trim, numbers to 2dp, row order, and PROCTRAN_REF (documented exclusion) — nothing else.

6. KNOWN LIMITATIONS (documented / intentional differences and coverage gaps)

KL-CREACC-BAL — CREACC opening balance is not part of the REST surface

COMMAREA COMM-AVAIL-BAL/COMM-ACT-BAL (50, 100, -5000, -125000) are written by COBOL CREACC; POST /banking/account has no balance field (api-contract.md) and the migrated account opens with 0.00. This matches the legacy web path: src/webui/.../web/db2/Account.createAccount inserts 0.00,0.00. Account number, type, rate, overdraft, dates, CONTROL and PROCTRAN all match in these flows; BNK1CAC/create-ok (3270 path) matches fully.

Flows: CREACC/type-isa, CREACC/type-loan, CREACC/type-mortgage, CREACC/type-saving

KL-UPDACC-TYPE — UPDACC invalid account type rejected by the REST layer

Legacy COBOL UPDACC writes ACCOUNT_TYPE=CHEQUE (pre-existing defect 9); the migrated PUT /banking/account/6 returns 400 "Account type CHEQUE is not supported." (updacc/UpdateAccountController.VALID_ACCOUNT_TYPES), exactly like the legacy Liberty AccountsResource.updateAccountInternal (validateType, HTTP 400) that fronted UPDACC for the React UI. Intentional per tickets.md T-07 ("blank or invalid type -> 400").

Flows: UPDACC/invalid-type

KL-RANDOM-CUST — INQCUST "random customer" (custno 0) picks a different customer

Legacy always returns customer 0000000001 for both CBSA_RANDOM_SEED=42 and 7 (GENERATE-RANDOM-CUSTOMER is computed from NCS-CUST-NO-VALUE, so the draw collapses to 1); the migrated service draws from CbsaRandom stream 100 (seed+100) over the highest customer number and returns 0000000022 (seed 42). Documented as a known deviation before this run in screens/TranscriptReplayTest.KNOWN_DEVIATIONS and InquireCustomerTranscriptReplayTest. The outcome kind (success) and DB state match.

Flows: INQCUST/random-seed-42, INQCUST/random-seed-7, BNK1DCS/lookup-non-numeric

Coverage notes

  • PROCTRAN_REF excluded from every comparison (documented: docs/migration/inventory.md "PROCTRAN_REF is the CICS task number (Java: per-JVM sequence) and is excluded from parity comparisons"). Observed: legacy writes the task EIBTASKN on every row of a task (e.g. DELCUS 4 rows all 000000000100); Java increments per row and CRECUST uses taskn+1 (credit check consumes one number). All other PROCTRAN columns are compared.
  • ABNDPROC/record: not comparable - the migrated service has no REST trigger for ABNDPROC (only GET /banking/abend).
  • BANKDATA (batch) is not replayed per flow; its output is the canonical seed itself, and the seed loaded by both sides was verified identical (full CUSTOMER/ACCOUNT/PROCTRAN/CONTROL dump) before every flow.
  • Migrated EIBTASKN is set through a parity-only test seam (parity/tools/ParityServer.java: resettable TaskNumberSupplier subclass + /__parity reset/exec/dump endpoints); all business beans are the unmodified target/classes.
  • 3270 screen flows have no REST surface: they are driven in-process through com.ibm.cics.cip.bank.core.screens handlers (parity/tools/ScreenParity.java). RETURN COMMAREA bytes are not compared (Java keeps a symbolic state map).
  • React unit tests are not runnable in this environment: ReferenceError: TextDecoder is not defined (enzyme -> cheerio -> undici needs Web APIs absent from the CRA jsdom env; fails in src/setupTests.js before any test).
  • React UI was not driven end-to-end against the migrated service in this round; REST flows use the exact payloads in api-contract.md that the UI sends.
  • Single-node H2 only; the postgres profile was not exercised by this parity run.
